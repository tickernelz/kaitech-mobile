# Development

Needs Node 24 (`.nvmrc`). The `android/` and `ios/` folders are generated by `npx expo prebuild` and are not in the repo; change native behaviour through `app.json`, `app.config.ts`, and config plugins.

```bash
npm ci
npm run lint
npm run typecheck
npm test
npx expo run:android   # development build on an emulator or device
npm start              # Metro for the development build
```

Add packages with `npx expo install <package>` so their versions match the SDK.

## Languages (en and id)

Every text shown to the user comes from a translation catalogue, one file per language: `src/i18n/locales/en.json` and `src/i18n/locales/id.json`. Other catalogues (for example OS permission texts) only need to sit as an `en.json` and `id.json` pair in any folder under `src/i18n/`.

The CI gate `npm run i18n:check` fails the build when, within one pair:

- a key is missing or extra in one of the languages,
- a value is empty or not a string,
- a `{{name}}` placeholder differs between languages,
- one of the files is missing.

OS permission texts and the per-language app name live in `src/i18n/native/`, wired through `locales` in `app.json`. Lint (`i18next/no-literal-string`) rejects text written directly in JSX, including `label`, `title`, `placeholder`, and `accessibilityLabel`.

Libraries: `expo-localization` + `i18next` + `react-i18next`. Chat texts live in the `chat` namespace (`src/i18n/chat/en.json`, `id.json`), called with `useTranslation('chat')`.

- `expo-localization` is the official Expo module for reading the device language; on Android the device language can change without a restart, so it is read again every time the app becomes active.
- `i18next` switches the language while the app runs (`changeLanguage`) and `react-i18next` re-renders the screens that use it, so the choice in Settings applies without a restart. Plurals and interpolation use the `Intl` built into Hermes.
- Alternatives not used: `i18n-js` has no hook that re-renders components when the language changes; Lingui needs a Babel macro and a catalogue compile step.

The initial language follows the device (`id` or `in` becomes Indonesian, anything else English). The choice in Settings (Device language, English, Bahasa Indonesia) is stored in `expo-sqlite/kv-store` and read synchronously before the first screen, so there is no language flash. Dates and numbers are formatted through `useFormatters()` with `Intl` in the chosen language. Server errors are read from the stable `error_code` and translated by the app (`src/auth/errors.ts`); sentences from the server are never shown.

## Sign-in

The Sign in button on the welcome screen opens the default server directly: its address is the link domain (`KAITECH_LINK_HOST`, `lab0.kaitech.io`) and its database is the repo variable `KAITECH_DEFAULT_DB` (`lab0`, not a secret), both read at build time. "Use another server" on the welcome screen and in Add account from Settings opens a form for the server address and database; the server address is required, the database may be empty for a single-database server, both are checked for shape before the browser opens, and "Use lab0.kaitech.io" returns to the default. A database that does not exist cannot be detected before the browser opens, because `/web/login?db=<name>` always answers 200. A build missing either variable has no default server: the Sign in button opens the form described above. Accounts are stored per server and database (`u{uid}_hash(origin|db)`), so the default account and accounts on other servers do not overwrite each other.

The app opens `/kaitech_mobile/authorize` on the chosen server in the system browser with PKCE S256, then exchanges the code at `/kaitech_mobile/token`. The device token is stored in the Keychain/Keystore (`expo-secure-store`, this device only, only while unlocked); account data that is not secret is stored in `kv-store`. Server contract: the README of the `kaitech_mobile` module on lab0.

The server returns the code to the App Link/Universal Link `https://<link domain>/kaitech_mobile/callback`; custom schemes are not used. The link domain is read at build time from the `KAITECH_LINK_HOST` variable (not from the repo); its value is `lab0.kaitech.io`, so that host name is visible in the public APK and IPA. A build without that variable still runs, but the sign-in screen shows a message that the link domain is not set. That domain must serve `/.well-known/assetlinks.json` with the certificate fingerprint from [App identity](app-identity.md) and be registered in the server's `kaitech_mobile.redirect_uris`; lab0 meets both (the parameter is empty, so the server uses `web.base.url` + `/kaitech_mobile/callback`). Another server entered by the user still returns the code to this link domain, so that server must register `https://lab0.kaitech.io/kaitech_mobile/callback` in `kaitech_mobile.redirect_uris`.

## Passkeys

Settings > Security > Passkeys adds a passkey through the phone's passkey manager (Credential Manager on Android, `ASAuthorizationPlatformPublicKeyCredentialProvider` on iOS) with the same server calls as the web `auth_passkey` widget: `res.users.action_create_passkey` (with the password check when the server asks for it), the creation options from `context.registration` passed unchanged to the native module `modules/kaitech-passkey`, then `auth.passkey.key.create.create` and `make_key` with the WebAuthn answer. The server accepts the `android:apk-key-hash:` origin of the release certificate (`kaitech_mobile` README in lab0, section Native passkeys). On iOS the server accepts passkeys only once `kaitech_mobile.apple_app_ids` holds the app's Team ID, so adding one from an iPhone is not proven. A phone without a passkey manager gets a message to turn one on; cancelling the phone's dialog shows no error.

## Icons and splash

`node scripts/brand-assets.mjs` regenerates every icon, the small Android notification icon, and the splash images from the K letter and the gradient bar of the Kaitech logo (needs `inkscape`). In-app icons are drawn in-house and live only in `src/ui/icons` (component `Icon`, variants `line` and `fill`); `node scripts/icon-sheet.mjs <out.png>` makes a contact sheet of the whole set at 16/20/24/32 px, light and dark. The SVG sources are in `assets/brand/`. The splash background colour equals the theme canvas colour (light `#FAF9FC`, dark `#110B18`), so there is no white flash when JS takes over. The brand font Plus Jakarta Sans (OFL, `assets/fonts/OFL.txt`) is embedded through the `expo-font` plugin; body text uses the system font.

## Motion

Every animation takes its duration and curve from `src/theme/motion.ts`: `quick` 120 ms for press feedback, `base` 180 ms for small state changes, `slow` 240 ms for exits, `hero` 320 ms for first screens, `axis` 300 ms for step changes; the `standard` curve for things that move on screen, `expo` for things that enter, `exit` for things that leave, and the `spring` set for Material 3 shapes. Sheets and dialogs fade (`src/ui/Modal.tsx`), screens use the platform push.

`useReduceMotion()` (`src/theme/reduceMotion.ts`) follows the system Reduce motion / Remove animations setting live. When it is on, screens change without a transition, `Modal` opens without one, Reanimated controls drop their movement (they jump or only fade), and the chat scrolls to a sent message or a jumped-to message without animating. Use `Modal` from `src/ui/Modal.tsx` and `useReduceMotion()` for new code; `useReducedMotion` from `react-native-reanimated` reads the setting once at start and is not used.
